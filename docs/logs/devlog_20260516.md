  - ユーザーが「登録ページを開く」ボタンを能動的に押すと register.html で再登録できる

### 運用手順（次回セッションで実施）

#### Step 1. ドメイン取得（未取得の場合）
- お名前.com / Cloudflare Registrar / Google Domains いずれかで取得
- 例：`magonotec.com` `magonotec.app` `magonotec.jp` など
- 送信専用ならサブドメインでもOK（例：`mail.magonotec.com`）

#### Step 2. Resend 側の作業
1. Resend ダッシュボード → **Domains** → **Add Domain**
2. 取得した独自ドメインを入力
3. Resend が以下のDNSレコードを表示するので、ドメインのDNS管理画面に追加：
   - **SPF（TXT）**: `v=spf1 include:amazonses.com ~all`
     （Resend は AWS SES バックエンド。Resend ダッシュボードに表示される値をそのまま使う）
   - **DKIM（CNAME × 3 または TXT）**: Resend が発行する `resend._domainkey...` 系レコード
   - **MX（任意）**: Resend が指定する場合のみ
   - **Return-Path（CNAME、推奨）**: 認証強化用
4. DNS反映を待つ（数分〜最大48時間、通常は15分以内）
5. Resend ダッシュボードで **Verified** バッジが付いたら認証完了

#### Step 3. Render 環境変数の更新
1. Render ダッシュボード → `magonotec-api`（webサービス） → **Environment**
2. `RESEND_FROM_EMAIL` を更新：
   - 旧: `onboarding@resend.dev`（または未設定）
   - 新: `noreply@<取得した独自ドメイン>`（例：`noreply@magonotec.com`）
3. **重要**：作業1で追加した Cron Job `magonotec-weekly-reports` の環境変数にも同じ値を設定
   - web と cron で別サービスのため、両方更新が必要
4. Render が自動で web サービスを再デプロイ。Cron Job は次回スケジュール時に新環境変数を反映

#### Step 4. テスト
1. **pairing URL 送信テスト**: 新規 Stripe Test 課金 → `subscriptions.family_email` に届くか確認
   - 受信トレイ（spam ではなく）に届くこと

2. **週次レポート手動実行テスト**: Render ダッシュボード上で Cron Job を手動 trigger
   - メール受信を確認
   - 同じく受信トレイ着・From 表示自然を確認
